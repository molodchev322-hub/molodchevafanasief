**Учебный проект по построению интеллектуального ассистента на основе
Graph RAG и LLM-агента.**

Ассистент помогает диспетчеру вымышленной сервисной компании «ПолярТех»
находить неисправности оборудования, определять необходимые запасные
части, учитывать их замену и получать актуальные сведения о наличии и
стоимости из ERP-системы.

## Задача проекта

При обслуживании холодильного оборудования диспетчеру необходимо
сопоставить код ошибки с неисправным узлом, определить установленную
деталь, проверить, не снята ли она с производства, и найти актуальную
замену. Эти сведения распределены между руководствами, сервисными
бюллетенями, регламентами и отчётами инженеров.

Информация об остатках и ценах хранится отдельно --- в ERP-системе.
Поэтому одного поиска по текстовой близости недостаточно: для ответа
может потребоваться восстановить цепочку связей между несколькими
документами и обратиться к внешнему источнику данных.

Проект объединяет граф знаний, семантический поиск и агента, который
вызывает специализированные инструменты.

## Возможности

-   **Извлечение знаний из документов:** выделение сущностей и отношений
    между ними.
-   **Построение графа знаний:** объединение фактов из разных документов
    с сохранением источников.
-   **Поиск по графу:** локальный поиск по связанным сущностям и
    глобальный поиск по сообществам.
-   **Сравнение подходов:** базовый векторный RAG, Graph RAG и агентный
    режим.
-   **Работа с ERP:** получение сведений о запасах, ценах и заказах.
-   **LLM-агент:** выбор инструментов и последовательное выполнение
    шагов для ответа на вопрос.
-   **Проверка ответов:** тесты, оценка качества извлечения и сравнение
    режимов.

## Архитектура

``` mermaid
flowchart TD
    A["Документы корпуса"] --> B["Разбиение на чанки"]
    B --> C["Извлечение сущностей и отношений"]
    C --> D["Граф знаний"]
    D --> E["Выделение сообществ и сводки"]
    D --> F["Локальный поиск"]
    E --> G["Глобальный поиск"]

    Q["Вопрос пользователя"] --> H["LLM-агент"]
    H --> F
    H --> G
    H --> I["ERP-инструменты"]
    F --> J["Ответ с источниками"]
    G --> J
    I --> J
```

### Режимы работы

  -----------------------------------------------------------------------
  Режим                               Назначение
  ----------------------------------- -----------------------------------
  `baseline`                          Базовый поиск по векторному индексу
                                      (обычный RAG)

  `local`                             Локальный поиск по графу знаний

  `global`                            Глобальный поиск с использованием
                                      сообществ графа

  `agent`                             Агент, который выбирает инструменты
                                      и при необходимости обращается к
                                      ERP
  -----------------------------------------------------------------------

## Запуск

### Требования

-   Python 3.11 или 3.12.
-   Docker и Docker Compose.
-   Ollama версии 0.15.4 или новее.
-   `make`. В Windows команды проекта рекомендуется выполнять через WSL.
-   Свободное место и оперативная память для локального запуска моделей.

### 1. Подготовка моделей

Установите Ollama и загрузите модели:

``` bash
ollama pull qwen3:4b-instruct-2507-q4_K_M
ollama pull bge-m3
```

### 2. Настройка окружения

В корне проекта создайте `.env` на основе шаблона:

``` bash
cp .env.example .env
```

Для запуска Ollama на компьютере в `.env` используется адрес:

``` dotenv
LLM_BASE_URL=http://host.docker.internal:11434/v1
LLM_MODEL=qwen3:4b-instruct-2507-q4_K_M
EMBED_MODEL=bge-m3
LLM_API_KEY=ollama
```

Не публикуйте `.env` и реальные API-ключи в репозитории.

### 3. Запуск сервисов

``` bash
make up
```

Команда собирает и запускает сервисы приложения и ERP. Убедитесь, что
Ollama запущена и доступна по адресу из `.env`.

### 4. Построение индекса

``` bash
make index
```

Команда выполняет индексацию корпуса, строит граф знаний и формирует
сообщества.

### 5. Первый запрос

``` bash
make ask MODE=agent
```

Можно указать собственный вопрос:

``` bash
make ask MODE=local Q="Какую деталь заказать при ошибке E-17 на AR-210?"
```

Подробная инструкция, в том числе вариант запуска без Docker, находится
в [`docs/setup.md`](docs/setup.md).

## Основные команды

  -----------------------------------------------------------------------
  Команда                             Назначение
  ----------------------------------- -----------------------------------
  `make up`                           Запустить приложение и ERP

  `make index`                        Построить индекс, граф и сообщества

  `make ask MODE=baseline`            Выполнить запрос в базовом RAG

  `make ask MODE=local`               Выполнить локальный поиск по графу

  `make ask MODE=global`              Выполнить глобальный поиск

  `make ask MODE=agent`               Выполнить запрос через агента

  `make test`                         Запустить все тесты

  `make lint`                         Проверить код с помощью Ruff

  `make eval-all`                     Сравнить четыре режима на наборе
                                      вопросов

  `make eval-extraction`              Оценить качество извлечения
                                      сущностей и связей

  `make down`                         Остановить сервисы
  -----------------------------------------------------------------------

## Пример использования

В корпусе проекта рассматривается ситуация с ошибкой `E-17` на
оборудовании `AR-210`.

Вопрос:

> Какую деталь заказать при ошибке E-17 на AR-210, есть ли она на складе
> в Казани и сколько она стоит?

Для ответа системе необходимо:

1.  Найти значение кода ошибки.
2.  Определить соответствующий узел оборудования.
3.  Найти установленную деталь и проверить сведения о её замене в
    документах.
4.  Обратиться к ERP за остатком и стоимостью.
5.  Сформировать ответ с указанием источников и выполненных шагов.

В документации проекта приведены ожидаемые результаты контрольного
сценария. Фактический результат запуска зависит от используемой
конфигурации и должен быть проверен повторным прогоном.

## Тестирование и оценка

Запуск полного набора тестов:

``` bash
make test
```

Проверка стиля и статических ошибок:

``` bash
make lint
```

Сравнение режимов:

``` bash
make eval-all
```

Оценка извлечения:

``` bash
make eval-extraction
```

Метрики и порядок интерпретации результатов описаны в
[`docs/evaluation.md`](docs/evaluation.md).

**Важно:** JSON-артефакты и PDF-отчёт в исходном архиве могут содержать
результаты предыдущего прогона. Перед финальной сдачей необходимо
пересобрать индекс, повторить оценку и обновить отчёт. Не следует
выдавать старые метрики за результаты новой конфигурации.

## Важные замечания перед сдачей

1.  Выполните `make index`, `make test`, `make lint`, `make eval-all` и
    `make eval-extraction`.
2.  Проверьте, что результаты в `artifacts/` соответствуют последнему
    прогону.
3.  Обновите `REPORT.pdf` по требованиям из
    [`docs/submission.md`](docs/submission.md).
4.  Убедитесь, что в репозитории нет `.env`, токенов, паролей и других
    секретов.
5.  Добавьте тег `v1.0` к коммиту, который отправляете на проверку, если
    это предусмотрено правилами сдачи.
